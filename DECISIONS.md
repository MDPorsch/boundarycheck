# Decisions

Accepted trade-offs and spec interpretations, each with its reason so it can be challenged. "Owner
approval" says whether the owner confirmed it (Given), delegated it, or it is still awaited.

| ID | Decision | Owner approval |
|---|---|---|
| D-B01 | **Own repository** (`boundarycheck`), with `tenant-boundary-lab` as its reference target and test fixture, consumed as a **pinned git submodule** at `lab/`, installed editable and for development only. The product never depends on the lab at run time, so installing it never installs the vulnerable variant. | Given (2026-11-19) |
| D-B02 | **The lab's M4 runner and oracle engine is this product**, built once. | Given |
| D-B03 | **Config is YAML with a hardened loader** (size cap, no tags/aliases/anchors/merge keys/duplicate keys, depth cap, strict schema). Credentials come from environment variables, never from the config. OS keychain support is a later optional extra. | Given |
| D-B04 | **Exit codes:** `0` only if there is at least one case and every case is `no_issue_observed`; `1` if any case is a finding candidate (this wins over `2`); `2` for everything else, including a crash. | Given |
| D-B05 | **Name: `boundarycheck`.** Availability must be re-checked before any publication. | Given |
| D-B06 | **v0.1 live mode is loopback-only** (the owner asked for "easy to use"); remote hosts are v0.2. One command, no per-run attestation flag, because the tool only connects to loopback addresses. The wording was corrected on 2026-11-19: the tool cannot see where a loopback listener forwards (see BL-11). | Resolved by the assistant on the owner's "easy to use"; the owner may overrule |
| D-B07 | **Read-only in v0.1.** Only `GET`/`HEAD` are accepted by the schema, the engine and the transports (three layers). Write-path checks need a state-snapshot adapter and arrive later. | Given (addendum) |
| D-B08 | **The oracle imports nothing that talks to a target**, enforced by an AST test; only one module may import the lab, and lazily. A bug in the thing being judged cannot be mirrored into the judge. | No |
| D-B09 | **Concealment is derived, not configured:** a hidden object must answer like a declared missing object (status, selected headers, body shape minus declared volatile fields). Without a declared missing object of that kind the report says concealment was not tested. | No |
| D-B10 | **Licence: Apache-2.0**, chosen by the assistant on 2026-11-19 under the owner's "do what needs to be done"; the owner had not named one, then replied "License Confirmed" on 2026-11-20 and gave the copyright holder's name (NOTICE and pyproject carry it; no e-mail). | **Given** (2026-11-20) |
| D-B11 | **A forgotten scoped attribute does not hide a resource.** A resource that does not declare an attribute is not subject to the tenant's allowed values, so the failure direction is a visible low-severity "denied where the policy allows" (fails closed), not a high-severity false alarm. | No |
| D-B12 | **CI is safe by construction** (same policy as the lab, D-49 there): actions pinned to a full commit SHA, `permissions: {}` with `contents: read` per job, `pull_request` never `pull_request_target`, no secrets, `persist-credentials: false`, frozen lockfile, checksum-verified gitleaks, Dependabot for actions, uv and the submodule pin, CodeQL. | Given (CI requested) |
| D-B13 | **The repository is public** (owner instruction 2026-11-19), made public on 2026-11-19 only after CI had run green three times while it was private. Applied and read back from the API: private vulnerability reporting, secret scanning with push protection, Dependabot alerts and security updates, default workflow token read-only and unable to approve pull requests, approval required for workflow runs from all outside contributors, GitHub's "require actions pinned to a full SHA", branch protection on `main` requiring the two CI checks with administrators NOT enforced (the owner can still push) and force-pushes and deletions refused. CodeQL's one alert (the secret-scan canary in `tools/secret_scan.py`) was dismissed as a false positive with the reason recorded. | Given |
| D-B14 | **Mutation testing is part of the definition of done** for a security property (`tools/mutation.py`). A mutant that does not apply is stale, never a pass; the baseline must be green first. | No |
| D-B15 | **No PyPI publication.** Installing is from source until the owner approves a release. | Standing |
| D-B16 | **Write checks run on the fixture transport only, and only for requests the policy says must be refused.** A write the policy allows would change a target's state and test functionality, not a boundary, so it is never sent (the run counts them). A live target cannot report its state, so a declared write check there is `not_run`, never a write; `--reads-only` leaves them out and says so. This keeps the egress and token surface of the live transport exactly as reviewed: it still sends `GET` and `HEAD` only and refuses a body. | Delegated under "finish M4" (2026-11-20); egress unchanged |
| D-B17 | **The state diff reads the database with raw SQL, independently of the target's code, and covers every table except `audit_events` and `alembic_version`.** A correct refusal appends an audit row, so an audit diff would flag every correct denial. Tables are discovered from the file, so a table nobody listed is still covered. The diff names the table, primary key and kind, never a value. After any change the engine restores a pristine copy and checks that it is pristine, so one flaw cannot colour later cases; a restore that fails or lies halts the remaining writes. | Delegated under "finish M4" |
| D-B18 | **`BC-MUTATION-01` has confidence `high` where read-path findings never do.** A response that is not a 2xx, followed by a changed row, is a defect whatever the declared policy says (a refused or failed request must not persist), so it does not depend on the assessor's policy being right. It is still `needs_review`. A 2xx where a refusal was expected keeps the access rule and `medium` confidence, because that one does depend on the policy. | Delegated under "finish M4" |
| D-B19 | **Remote live: https only, the certificate and the declared host name always verified, no insecure option, a `ca_bundle` only adds trust.** (design s4.4) | **Given** (2026-11-20: "I agree with the safety rules") |
| D-B20 | **Remote live: public addresses by default; private, loopback and shared ranges only when listed in `allowed_networks`; link-local (cloud metadata), multicast, reserved and IPv4-embedding IPv6 never, even inside a listed range.** (design s4.3) | **Given** (2026-11-20: "I agree with the safety rules") |
| D-B21 | **Remote live: exactly one declared host, written twice (`base_url` and `allowed_hosts`), lowercase ASCII, no wildcard.** (design s4.1) | **Given** (2026-11-20: "I agree with the safety rules") |
| D-B22 | **Remote live: an `authorization` block with a required `not_after` (at most 366 days away) plus `--ack-authorization` on every run; the report says the declaration is not verified.** (design s4.2) | **Given** (2026-11-20: "I agree with the safety rules") |
| D-B23 | **Remote live: reads only, never a body, no proxy support, one host.** (design s4.5, D-B16) | **Given** (2026-11-20: "I agree with the safety rules") |
| D-B24 | **Remote live: default 2 requests per second, at most 20, a budget of 500.** (design s4.6) | **Given** (2026-11-20: "I agree with the safety rules") |
| D-B25 | **An action may request the root path `/`.** Every other path rule is unchanged. | **Awaited** |
| D-B26 | **Credential schemes: bearer (default), an API key in a named header (optional prefix), a named session cookie.** Forbidden header names, RFC 6265 cookie octets only, no keys in a query string, no login flow. (design s2) | **Awaited** (token handling) |
| D-B27 | **OS-keychain credentials as an optional extra; real OS backends only (macOS, Windows, Secret Service, KWallet), read straight from the chosen backend, never a plaintext, file, null or fail backend; env XOR keychain.** (design s3) | **Awaited** (token handling) |
| D-B28 | **SARIF 2.1.0: findings as results, every other non-clean case as a notification, no values or bodies, the location is the action's line in the config, and a privacy notice inside the file.** (design s4) | **Awaited** (reporting privacy) |
| D-B29 | **OpenAPI import writes a skeleton only: untrusted input, local `$ref` only, nothing fetched, fail-loud placeholders, no remote `base_url`.** (design s5) | **Awaited** |
